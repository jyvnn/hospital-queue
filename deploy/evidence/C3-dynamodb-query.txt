## Notes
Two deviations from the task template, both documented: (1) the template used 'pk'; the real partition key found in the scan is queue_date, so the query uses queue_date = 2026-11-04 (the literal 'pk' query was not run: the table has no such attribute). (2) the template's '--scan-index-forward false' is rejected by AWS CLI v2 (see C3-dynamodb-query-FAILED-first-attempt.txt); the v2 form for descending order is --no-scan-index-forward.
Trace to a click: patient_checked_in items come from submitting the registration form (POST /patients/add). doctor_assigned comes from POST /patients/assign-doctor and consultation_completed from POST /patients/complete. The oldest item (patient 1, 12:52:03Z) was created by the Phase 5 verification script posting to /patients/add as the demo user, i.e. the same request the Registration form sends.
